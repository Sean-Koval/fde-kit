# Build

Build turns the validated approach into working value through small, observable increments.

## Objective

Create the working solution in small increments, validating assumptions and quality as the work progresses.

## Entry conditions

- A solution approach is credible enough to implement and test with real users or operations.
- The first increment has a value hypothesis, acceptance signals, and understood boundaries.
- The team has access to the required technical environment, dependencies, and decision-makers.

## Questions to answer

- What is the smallest increment that can deliver or test meaningful value?
- Which assumptions still need validation as the solution becomes real?
- How will the team verify functional quality, safety, performance, and maintainability?
- Which dependencies, decisions, or operating changes could block the next increment?

## Recommended activities

- Slice the work into small increments tied to user or operational outcomes.
- Build, test, and demonstrate each increment with representative data and real feedback where possible.
- Keep acceptance signals, risks, dependencies, and decisions current as evidence changes.
- Prepare production requirements alongside implementation rather than at the end of build.

## Expected deliverables

- Working increments that demonstrate the intended use.
- Evidence from tests, demonstrations, and user or operator feedback.
- Updated technical decisions, known limitations, and risk mitigations.
- A production-readiness plan covering the remaining deployment requirements.

## Exit criteria

- The solution satisfies its intended use for the agreed scope.
- Quality evidence and known limitations are understood by the relevant owners.
- A realistic production path exists, including accountable owners for deployment requirements.

## Common failure modes

- Building a large batch before checking whether it improves the target workflow.
- Measuring progress by completed tasks rather than working, validated value.
- Deferring security, observability, reliability, or support decisions until deployment.
- Allowing new requests to expand scope without returning to the agreed problem frame.

## Related capabilities

- Incremental delivery
- Acceptance testing and demonstration
- Technical decision recording
- Production-readiness planning

## Practice

Choose a proposed solution and define its smallest valuable increment. State the user outcome it should produce, the acceptance signal that would validate it, and one production requirement to address during the increment.
