Technical delivery · Enterprise integration

Land AI inside the customer’s control plane.

Experience

Existing inbox, case queue, operations console, approval surface, and user feedback.

Workflow

State machine, deterministic business rules, human review, retries, idempotency, and rollback.

AI runtime

Model routing, retrieval, prompts, tool calls, structured outputs, confidence signals, and traces.

Enterprise systems

ERP, CRM, document store, identity provider, policy services, data warehouse, and event bus.

Platform controls

Authentication, authorization, secrets, encryption, data residency, observability, cost, and incident response.

Integration contract: schemas, APIs, permissions, failure modes, latency budgets, and system owners.

Governance contract: allowed data, retention, model use, review policy, audit evidence, and change approval.

The enterprise architecture is layered so the team can reason separately about user experience, workflow state, AI behavior, systems of record, and cross-cutting controls.

Do not ask whether the whole workflow should use AI. Decompose it and assign each decision according to ambiguity, determinism, consequence, and reversibility.

Prove quality · Evaluation pack

Turn field failures into release evidence.

Cases

Representative set

Common, costly, risky, and adversarial examples.

Criteria

Outcome graders

Correctness, evidence, policy, abstention, and workflow result.

Analysis

Failure taxonomy

Model, data, tool, policy, integration, or human-interface cause.

Change

System revision

Prompt, model, retrieval, rule, UX, control, or process update.

Release

Regression + online

Offline gate, production traces, drift, and review burden.

Evaluate the system outcome. A fluent answer can still use the wrong evidence, call the wrong tool, violate policy, or create expensive review work.

Starting heuristic: begin with 30–50 representative cases, then add every meaningful production failure to the regression set.

The Evaluation pack combines cases, expected outcomes, graders, thresholds, failure analysis, and the release decision. The loop continues after launch.

Land production · Rollout plan

Autonomy advances only when evidence clears the gate.

Gate 0

Observe

Measure baseline, exception rate, handling time, and business outcome.

Pass: workflow and owner are known.

Gate 1

Assist

AI drafts or extracts; the operator remains in control.

Pass: utility exceeds added review burden.

Gate 2

Shadow

Run on live traffic without changing the production outcome.

Pass: eval and field performance agree.

Gate 3

Approve

AI proposes bounded actions; humans approve exceptions and risk.

Pass: controls and rollback work.

Gate 4

Bounded autonomy

AI acts only inside monitored permissions, limits, and stop conditions.

Pass: owner accepts residual risk.

Promote, hold, or roll back. Staying at assist, shadow, or approve can be the highest-value and safest production design.

The gates are control states, not a maturity contest. Each promotion needs named evidence and an explicit decision owner.

Transfer ownership · Operating plan

Day 2 begins before Day 1.

A production AI system is a service with probabilistic behavior.

Operate the workflow outcome, not only model uptime.

Observe

Quality, abstention, review load, drift, latency, cost, tool errors, and business result.

Respond

Alert severity, triage owner, fallback mode, user communication, and incident command.

Change

Version prompts, models, policies, evals, and integrations with approval and rollback.

Learn

Review traces, add regression cases, refresh training, and report measured impact.

Name three owners: business outcome owner, technical service owner, and risk/control owner. Record backup coverage and escalation paths.

The Operating plan captures service objectives, dashboards, alerts, incident flow, change control, ownership, and the review cadence.

Transfer ownership · Adoption

Ship a new operating habit, not a feature.

01 · Co-design

Build with operators

Use their cases, language, exception paths, and measures of success.

02 · Rehearse

Practice the fallback

Train normal work, low-confidence review, escalation, and incident behavior.

03 · Instrument

Watch behavior

Measure use, overrides, abandonment, review time, and outcome—not logins alone.

04 · Transfer

Make owners independent

Hand over runbooks, dashboards, evals, permissions, and change decisions.

Adoption signal

Operators choose the workflow for real work, trust the review path, and can explain when not to use it.

Exit signal

The customer can monitor, triage, change, and improve the system without the FDE as the daily operator.

Adoption is a behavior change and ownership transfer. The FDE stays close until the customer can run both the happy path and the exception path.

Compound learning · Product feedback

Send evidence upstream, then prove the response downstream.

Field signal

Observe pattern

Repeated failure, missing capability, control gap, or winning workflow.

Evidence

Package the case

Frequency, impact, traces, eval cases, workaround, and user context.

Roadmap

Route to owners

Product, research, platform, security, go-to-market, or enablement.

Change

Build reusable leverage

Model, API, control, component, pattern, documentation, or training.

Validation

Re-evaluate in field

Run the regression set and measure adoption and workflow impact.

Good field feedback changes a decision. It is specific enough to reproduce, important enough to prioritize, and closed with production evidence.

The FDE is a sensing surface for the product and model roadmap. Raw anecdotes become useful only when paired with frequency, consequence, traces, and reproducible cases.

Expand from measured proof, not enthusiasm.

Expand

The first workflow sustains value, controls hold, ownership is real, and the next workflow shares reusable architecture or learning.

Hold

Adoption, reliability, control ownership, unit economics, or evidence quality is not yet durable.

Stop or redesign

The workflow does not create net value, transfers unacceptable risk, or depends on permanent FDE heroics.

Starting heuristic: require a stable production cohort and an accountable Day 2 owner before funding the next deployment.

The Business case compares baseline with production evidence and makes the expand, hold, or stop decision explicit.
